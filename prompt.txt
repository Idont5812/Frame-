# Frame° — COMPLETE FRONTEND MODERNIZATION, PREMIUM UI/UX & INTERACTION OVERHAUL

Act as a world-class UI/UX designer, frontend architect, senior software engineer, motion designer, and design systems specialist.

Your mission is to transform the existing Frame° frontend into a sophisticated, visually rich, fluid, and professionally engineered media platform.

This is both a frontend modernization and UI/UX improvement project.

You must inspect the existing application, evaluate alternative frontend technologies, choose the most suitable architecture, and actually implement the improvements.

PRIMARY PRIORITY: Visual quality, interaction design, animations, and overall user experience.

Performance matters, but do not sacrifice beautiful UI, creative flexibility, or interaction quality simply to achieve smaller bundle sizes or synthetic benchmark improvements.

Preserve Frame°'s existing identity, branding, color palette, layout philosophy, and functionality.

1. FRONTEND TECHNOLOGY REEVALUATION & MIGRATION

Before changing the interface, thoroughly inspect the existing frontend architecture.

Evaluate whether the current framework and rendering architecture are appropriate for the application's long-term development.

Do not automatically retain React or JSX simply because the project currently uses them.

Preferred frontend stack

Use the following as the primary candidate:

- Svelte 5: Main frontend framework.
- SvelteKit: Application architecture, routing, and server-side capabilities where needed.
- TypeScript: Strict typing throughout the application.
- Tailwind CSS: Styling and responsive layouts.
- Bits UI or shadcn-svelte: Accessible, customizable UI primitives.
- Motion or native CSS animations: Sophisticated interactions and transitions.
- Lucide: Consistent outline iconography.

Evaluate compatibility and maintenance before selecting individual libraries.

Evaluate alternative technologies

Compare the following:

Frontend frameworks

- Svelte 5.
- Vue 3.
- SolidJS.
- Qwik.
- Preact.
- React.

Styling technologies

- Tailwind CSS.
- Modern CSS.
- CSS Modules.
- CSS variables and design tokens.
- SCSS where genuinely beneficial.

Animation technologies

- Native CSS transitions and keyframes.
- Svelte transitions.
- Motion.
- GSAP for complex animation sequences when justified.

Additional technologies

Evaluate Web Components, lightweight state-management solutions, native browser APIs, and other technologies where they provide meaningful benefits.

Migration requirements

If Svelte 5 is selected:

- Replace React components with native Svelte components.
- Eliminate JSX and unnecessary React dependencies.
- Migrate component state to Svelte 5 Runes.
- Migrate hooks and lifecycle logic appropriately.
- Reimplement routing using SvelteKit.
- Migrate existing styles to Tailwind and reusable CSS.
- Reimplement animations using appropriate Svelte and CSS capabilities.
- Migrate all existing component functionality.
- Preserve API integrations.
- Preserve authentication and application state.
- Maintain existing backend compatibility.

Do not mechanically translate React syntax into Svelte syntax.

Reconsider the architecture and implement each feature using the target framework's strengths.

Important: Do not migrate the backend language simply because the frontend is changing. Keep the existing backend unless a separate, evidence-based architectural improvement is justified.

3. GLASSMORPHISM & TRANSLUCENT UI

Introduce a refined glassmorphism aesthetic throughout Frame°.

This is a core visual requirement, not an optional decoration.

Glass design characteristics

- Semi-transparent dark surfaces.
- Visible background blur using backdrop-filter.
- Subtle translucent borders.
- Soft ambient shadows.
- Layered depth between floating elements.
- Smooth transparency and blur transitions.
- Carefully controlled opacity.
- Natural separation between overlapping surfaces.

Apply glass styling consistently to:

- Floating bottom navigation.
- Settings popovers.
- Grid selector.
- Dropdown menus.
- Search overlays.
- Modal dialogs.
- Floating controls.
- Context menus.

Use different transparency levels depending on component hierarchy.

Glass surfaces must genuinely reveal and blur the background rather than simply appearing as opaque dark boxes.

Maintain readability at every opacity level.

Avoid excessive blur, bright frosted-glass panels, distracting reflections, and unrelated color schemes.

Provide graceful fallbacks when backdrop-filter is unsupported.

4. FLUID ANIMATIONS & TRANSITIONS

Make the entire website feel alive and fluid.

Implement tasteful animations for:

- Page transitions.
- Navigation interactions.
- Dropdown menus.
- Popovers.
- Modal openings and closings.
- Settings panels.
- Video card hover states.
- Buttons and clickable elements.
- Search interactions.
- Loading indicators.
- Floating navigation.
- Grid layout changes.

Animation philosophy

Animations should feel:

- Smooth.
- Natural.
- Responsive.
- Sophisticated.
- Consistent.
- Visually satisfying.
- Subtle rather than distracting.

Suggested timings:

- Micro-interactions: 120–180ms.
- Dropdowns and popovers: 160–220ms.
- Panel transitions: 200–280ms.
- Page transitions: 200–350ms.

Use appropriate easing curves and spring-based motion where beneficial.

Avoid excessive bouncing, unnecessary movement, and animations that delay user interaction.

Use transforms and opacity wherever appropriate.

Respect prefers-reduced-motion.

Visual experience takes priority over minimizing every animation or transition.
